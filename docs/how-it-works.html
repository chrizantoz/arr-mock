How arr-mock works

A fake Sonarr, Radarr, Whisparr and Bazarr in one small Python file, so you can test an arr companion app end to end without installing the real services, finding API keys, or risking a real library.

The idea in one picture

A test run, step by step

  1. Make the files.synthlib.make(path, alang="fre") writes a real 30-second MKV with ffmpeg: French audio, no audio, an audio delay, 10-bit, whatever the case needs.
  2. Start the mock.srv = arr_mock.start(world) picks a free port and serves all four apps at once. The default world is one show with three episodes, one missing episode and one movie, matching those files.
  3. Point your app at it.Set its Sonarr URL to http://127.0.0.1:PORT/sonarr, Radarr to /radarr, Bazarr to /bazarr, API key test. Same for a Docker build of your app.
  4. Let it work.Your app lists the library, probes the files, finds the French episode, and presses whatever buttons it presses: a rescan, a search, a subtitle request.
  5. Read what it sent.srv.calls holds every write with app, method, path and body. Assert the rescan went to Sonarr, the search carried the right episode id, Bazarr got the PATCH.
  6. Turn on chaos, run again.srv.chaos = arr_mock.chaos() and the same run must now finish degraded, keep its data, and write nothing by accident. Set it back to None and the next run must be clean.

Chaos mode

The whole thing in code

import arr_mock, synthlib

W = arr_mock.default_world("/data/tv", "/data/movies")    # one show, three files, one missing episode, one movie
synthlib.make(W["files"][1]["path"], alang="fre")         # S01E02 really is French now
srv = arr_mock.start(W)                                   # http://127.0.0.1:<port>/sonarr … API key "test"

run_my_app(sonarr=f"http://127.0.0.1:{srv.server_address[1]}/sonarr", key="test")

writes = [c for c in srv.calls if c["method"] != "GET"]
assert any(c["body"].get("name") == "EpisodeSearch" for c in writes)   # it asked Sonarr to look for a better copy

srv.chaos = arr_mock.chaos()                              # now break things
run_my_app(...)                                           # must finish degraded, write nothing
srv.chaos = None

What it answers

appendpoints
Sonarr, Whisparrseries, series/{id}, episode?seriesId=, episodefile?seriesId=, episodefile/{id}, series/editor, tag, rootfolder, system/status, command, queue, history, blocklist, notification
Radarrmovie, movie/{id}, moviefile?movieId=, moviefile/{id}, movie/editor, plus the shared ones above
Bazarrepisodes/wanted, movies/wanted, episodes, episodes/history, movies/history, subtitles (PATCH search), providers/*, system/status
controlGET /__calls lists the recorded writes, POST /__reset clears them

It is deliberately shallow. Writes are accepted and recorded, never validated, and there is no search, no download client and no quality logic. If your app needs an endpoint that is missing, it is usually a three-line addition.

arr-mock was born inside Auditarr, where it runs the end-to-end and chaos tests in CI. Source and README: github.com/chrizantoz/arr-mock. GPL-3.0.
